# API Gateway для интеграции с DSP

## Выбор типа шлюза

Bid-запрос от DSP-партнёра целиком укладывается в бюджет P95 ≤ 80 мс, поэтому шлюз на этом пути не может быть «тяжёлым» — каждая миллисекунда накладных расходов сокращает бюджет, доступный Сервису ставок. Рекомендуется высокопроизводительный edge-прокси (класс Envoy / NGINX с модулями аутентификации и ограничения частоты запросов), а не универсальная платформа API-менеджмента с богатой оркестрацией трансформаций полезной нагрузки — такие возможности здесь не нужны, а их накладные расходы на пути ≤ 80 мс не оправданы.

**Бюджет латентности самого шлюза:** в пределах 5–10 мс из общих 80 мс P95 (аутентификация + маршрутизация + rate limiting), оставшееся — Сервису ставок и Сервису выдачи.

Тот же шлюз обслуживает и остальной внешний трафик (Рекламодатель, Пользователь), но для маршрутов DSP-интеграции применяется отдельный, более строгий набор политик, описанный ниже.

## Маршрутизация запросов на ставки

```
POST /rtb/bid  →  gRPC-вызов EvaluateBid к Сервису ставок
```

- Маршрут выделен в отдельный upstream-пул с приоритетным распределением ресурсов — не делит пул соединений с маршрутами Рекламодателя/Пользователя, чтобы всплеск не-RTB трафика не увеличивал латентность bid-пути.
- Version-заголовок / путь фиксирует версию контракта OpenRTB — позволяет вводить новых DSP-партнёров с другой версией протокола без изменения Сервиса ставок (шлюз транслирует к единому внутреннему формату `BidContext`).

## Ограничение частоты запросов (Rate Limiting)

- **Алгоритм:** token bucket на партнёра (`dsp_partner_id`, определяется по ключу аутентификации) — сглаживает всплески без резкого обрыва легитимного трафика, в отличие от жёсткого fixed-window.
- **Квота на партнёра** — задаётся индивидуально по контракту (например, согласованный при подключении лимит: ≥ 18 000 RPS суммарно на промежуточном этапе, с ростом до 50 000 RPS на целевом); превышение — `429 Too Many Requests` с `Retry-After`.
- Отдельный, более щедрый общий лимит на защиту инфраструктуры в целом (защита от аномального трафика даже от легитимных партнёров, например при их внутреннем сбое retry-шторма).

## Аутентификация

- **Mutual TLS** между DSP-партнёром и шлюзом — стандарт для программатик-интеграций такого уровня, не требует передачи секретов в теле/заголовках запроса.
- Дополнительно — статический API-ключ партнёра в заголовке как вторичный фактор идентификации для маршрутизации и rate limiting (проще сопоставить `dsp_partner_id`, чем разбирать сертификат на каждый запрос).
- Ключи и сертификаты — per-partner, с возможностью мгновенного отзыва без релиза шлюза (конфигурация партнёров — внешняя относительно кода шлюза).

## Circuit Breaker (Шлюз → Сервис ставок)

Защищает и Сервис ставок от каскадной перегрузки при деградации, и DSP-партнёра — от долгого ожидания ответа, которого не будет:

- **Порог открытия:** доля ошибок/таймаутов > 50% за скользящее окно 10 секунд, либо 20 последовательных неудачных вызовов.
- **Поведение при открытой цепи:** Шлюз немедленно возвращает `204 No Content` (AdScale не участвует в аукционе) вместо ожидания таймаута — это единственно корректный ответ с точки зрения контракта OpenRTB, не создающий у партнёра впечатления сбоя протокола.
- **Half-open:** одна пробная заявка раз в 5 секунд; несколько последовательных успехов подряд (не одна) требуются для полного закрытия цепи — избегаем «дребезга» при частично восстановленном сервисе.
- Состояние цепи (open/half-open/closed) экспортируется как метрика — см. «Мониторинг».

## Мониторинг времени отклика

- **P95/P99 latency** запроса `/rtb/bid` — основная метрика соответствия SLA (порог тревоги — приближение к 80 мс P95, не по факту превышения).
- Разбивка латентности по сегментам пути (накладные расходы шлюза / Сервис ставок / Сервис выдачи) — чтобы деградация локализовалась без анализа логов вручную.
- Метрики по партнёру (`dsp_partner_id`) отдельно — деградация у одного партнёра не должна маскироваться общими агрегатами.
- Алерты: P95 > 70 мс (предупреждение, запас 10 мс до нарушения SLA) и P95 > 80 мс (критично, включая эскалацию); отдельно — алерт на открытие Circuit Breaker (само по себе сигнал деградации зависимости).
